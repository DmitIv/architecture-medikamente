# Task 4. Узкие места миграции (диаграмма Исикавы)

## Центральная проблема

Высокий риск деградации производительности, надёжности и качества данных (включая безопасность и соответствие требованиям к ПДн) при переходе от текущего ландшафта Excel/файлов/1С к целевой платформе MVP и дальнейшему росту нагрузки в несколько раз за счёт филиалов и цифровых каналов.

Планируемая миграция затрагивает базы данных и новые OLTP-хранилища, интеграции с 1С и лабораторией, бизнес-логику записи и учёта, инфраструктуру и организацию команд.

# Риски миграции: меры и приоритеты

Таблица сопоставлена с ветками [диаграммы Исикавы](./ishikawa-migration.drawio.png).

| Категория | Причина / риск | Мера смягчения | Приоритет |
|-----------|----------------|----------------|-----------|
| Инфраструктура | Недостаточная мощность под пиковые часы записи и отчётности | Нагрузочное тестирование до cutover; запас по CPU/RAM; план вертикального масштабирования на первом этапе | High |
| Инфраструктура | Нет отказоустойчивости, одиночный сервер | Резервирование БД, бэкапы с проверкой восстановления; для критичных сервисов — второй узел или облачный standby | High |
| Инфраструктура | Невозможность горизонтального масштабирования stateful-части | Проектировать stateless API за балансировщиком; вынести сессии в Redis; шардирование отложить до метрик | Medium |
| Архитектура и код | Монолитные связи и отсутствие границ доменов | Branch by Abstraction: фасады Patient/Appointment над легаси | High |
| Архитектура и код | Нет единого source of truth для пациента и платежей | Ввести CRM/Patient Service и биллинг как владельцев; синхронизация с 1С однонаправленно из нового контура где возможно | High |
| Архитектура и код | Нет data lineage | Каталог + конвейеры ETL с документированием источников| Medium |
| Данные и интеграции | Дубли Excel + 1С | Параллельный прогон и сверка; постепенное отключение ручного дубля | High |
| Данные и интеграции | Отсутствие стабильных API у легаси | Адаптеры, файловый обмен как временный мост, контрактные тесты | High |
| Данные и интеграции | Нет классификации и тегов | Движок классификации перед DWH, не грузить сырые PII в витрины | High |
| Процессы | Ручные операции без регрессионных тестов | Автотесты API и UI критичных сценариев; чек-листы ресепшена на пилоте | High |
| Процессы | Нет нагрузочных тестов | Сценарии: N одновременных записей, отчёт в конце дня | Medium |
| Процессы | Слабый мониторинг | Метрики SLA API, ошибки интеграций, дашборд для cutover-ночи | High |
| Люди | Недостаток опыта в DWH, Kubernetes, интеграциях 1С | Обучение, привлечение подрядчика на этап 0–1, парное программирование | Medium |
| Люди | Нет выделенной роли по миграции / данным | Назначить владельца миграции и data steward на время проекта | High |
