## Масштабирование

- Горизонтально масштабируются воркеры ingestion и воркеры классификации (стейтлесс, задания из очереди).
- Тяжёлый анализ содержимого (ML) выносится в отдельный пул с rate limit, чтобы не блокировать сквозную задержку batch-загрузок.
- Metadata Store и каталог — отдельный сервис с индексом по источнику, таблице, версии схемы.

## Метрики классификации

- Кол-во инцидентов связанных с ошибками классификации
- Параметр "уверенности" предсказания модели для тега
- Частичная асессорская разметка входящего потока автоматического тегирования с высокой степенью уверенности: каждый десятый присвоенный тег в категории для порога > 0.8 сбрасывается в отдельный топик для последующей ручной разметки и составления golden test на ее основе. При сильном понижении точности модели, переобучение.
- Кол-во тегов с порогом уверенности < 0.8
- Кол-во данных с тегов unknown

## Оптимизация системы

- Падение метрик качества - сигнал к переработке модели (в идеале, чувствительность метрик должна быть слегка завышена, чтобы сохранить SLA разметки)
- Возможность оптимизировать производительность системы на уровне архитектуру/отдельных частей на уровне кода или моделей/правил - есть регресс по метрикам с возможностью откатиться к старой модели
