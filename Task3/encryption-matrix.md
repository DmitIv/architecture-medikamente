# Матрица: данные и защита

Связь с Task 1 и Task 2. По строкам — классы; примеры в первом столбце кратко в скобках.

| 1. Данные | 2. В чём необходимость защиты | 3. Инструменты защиты |
|-----------|-------------------------------|------------------------|
| PII (ФИО, ДР, телефон, email, адрес, СНИЛС/паспорт при наличии) | 152-ФЗ, этика в медконтексте, репутация, фишинг; нужна конфиденциальность при хранении, передаче и показе | Хранение: TDE/LUKS/BitLocker на БД и томах, для особо чувствительных полей используем шифрование на уровне поля или секрет-хранилище, шифрованные бэкапы и KMS. Передача: TLS 1.2+ на API и порталах, VPN/mTLS филиал–ЦОД, защищённая почта. Использование: маскирование в UI где не нужен полный набор, в логах только внутренние ID, экспорт по ролям с аудитом |
| PHI (диагнозы, протоколы, назначения, анализы) | Врачебная тайна, 152-ФЗ, отраслевые требования | Хранение: как для PII плюс отдельная зона для BLOB/сканов, шифрованный object storage. Передача: TLS, по возможности mTLS с лабораторией по договору. Использование: доступ по ролям (врач и узкий круг), маскирование в отчётах, без PHI в общих аналитических витринах |
| Финансовые (платежи, чеки, проводки, суммы в договорах) | Налоговая и коммерческая тайна, требования к ПЦИ при работе с картами | Хранение: шифрование БД биллинга и 1С, контроль ключей, по необходимости иммутабельные бэкапы. Передача: TLS к платёжному провайдеру, в своей БД не хранить полные PAN, а только токенизация у провайдера. Использование: разделение ролей касса/бухгалтерия, маскирование в списках где достаточно |
| Кадровые (сотрудники, зарплата, кадровые документы) | ПДн работников, ТК и смежные нормы | Хранение: шифрование томов и БД кадрового контура, отдельные политики в AD/OU. Передача: TLS, DLP на каналах с файлами зарплаты. Использование: доступ HR и расчёта, минимизация в справочниках других систем |
| Логи и сервисные (трассировки, метрики, техжурналы) | Через логи утекают PII/PHI; логи нужны для расследований | Хранение: отдельный контур логов, шифрование на диске, умеренный TTL сырых логов. Передача: TLS/syslog over TLS в коллектор. Использование: маскирование и фильтрация на сборе, не писать тела запросов с PHI |
